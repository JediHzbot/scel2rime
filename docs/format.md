# `.scel` 容器格式

这是当前解析器所采用的结构假设，来自有限样本观察及合成测试；不是所有搜狗版本的格式规范。合成构造器与解析器一致，不构成对未知真实样本的独立证明。

本文只描述**容器结构**。格式标记不能判断词库内容的来源或授权。

## 两代容器

| 代次 | 头部长度 | 拼音编码 | 识别方式 |
|---|---|---|---|
| 新版（用户词库） | `0x1540` | 音节索引（u16） | `0x04` 处为 `DCS\x01` |
| 新版（内置词库） | `0x1540` | 词条区不同 | `0x04` 处为 `ECS\x01` |
| 旧版 | `0x0040` | 纯文本 UTF-16 | 头部长度 `0x40` |

新版带一张音节表，词条只存索引，体积更小；旧版每条词条重复存拼音文本。`DCS` 是新版用户词库的默认输出，也就是搜狗词库制作工具和"我的词库"导出的那种，`scel2rime` 处理的就是它。

`ECS` 头部布局与 `DCS` 相同（词库名、分类、描述都能正常读出），但词条区结构不同：音节表之后的区域不直接是词条流，而是另有目录字段。已观察到的 ECS 样本来自安装包的 `scd` 目录。当前解析器不支持该变体，识别后拒绝；不根据魔数推断其他文件的来源。

拒绝一个文件比解析出一半数据更诚实：半截结果看起来像成功，用户会以为词库转完了。

## 新版头部

```
偏移     类型        含义
0x0000   u32         头部长度，恒为 0x1540
0x0004   char[4]     "DCS\x01"
0x0008   u32         容器版本，观察值 1
0x000C   byte[16]    摘要字段，尚未验证算法或覆盖范围
0x001C   utf16       词库 ID（如 "37121"）
0x0130   utf16[520]  词库名
0x0338   utf16[520]  分类
0x0540   utf16[4096] 描述
0x1540   —           正文开始
```

三个文本字段都是定长、NUL 填充、UTF-16LE。字段宽度固定，所以描述过长会被截断。

## 音节表（自 0x1540）

```
u32                 音节总数（实测 413，等于完整拼音音节集）
重复 count 次：
    u16             索引，从 0 递增
    u16             音节字节长度
    utf16[长度/2]   音节，纯小写 ASCII
```

音节表按字母序排列，`ü` 统一写作 `v`（`lv`、`nv`），没有声调数字。这与 Rime 的 `luna_pinyin` 约定一致，因此转换时拼音可以原样输出，不需要映射表。

## 词条流

紧跟音节表，直到文件结束。每条：

```
u16             标记位，观察值恒为 1，含义未知
u16             拼音字节数 = 音节数 × 2
u16[音节数]     音节索引，指向音节表
u16             词字节数
utf16[词]       词本身
u16             扩展块长度，观察值恒为 10
u16             词频等级 1..10
byte[8]         保留，全 0
```

实测算术：`2 + 2 + 2×音节数 + 2 + 词字节数 + 2 + 10`。

标记位暂按未知字段保留。样本扩展块长度为 10；实现接受 2–64 字节且必须完整，读取前两个字节作为权重。其他扩展块语义未验证。

## 词频

不是真实频次，是 1..10 的**等级**。同一个词库内可以据此排序，但跨词库不可比——这也是转换时要放大权重（默认 ×100）的原因，否则并进别的词典后区分度会被淹没。

## 一条实例

`宕机 / dang ji / 1`：

```
01 00                     标记
04 00                     拼音 4 字节
3b 00 84 00               两个音节索引
04 00                     词 4 字节
95 5b 3a 67               "宕机"
0a 00                     扩展块 10 字节
01 00 00 00 00 00 00 00 00 00   等级 1 + 保留
```

## 解析策略

解析器按结构走，不按长度猜：

- 每条词的音节数由**拼音字节数 ÷ 2** 得出，不由标记位或字符数推断——英文数字词（`x86`）的音节数本来就不等于字符数。
- 遇到不可能的字段值（拼音长度超过 512 字节、扩展块长度不在 2–64 字节范围或超出剩余数据）立即停止并记录警告，已解析的部分照常返回。截断的文件因此能救回大半内容，而不是整个失败。
- 文件短于头部长度属于结构性损坏，直接报错，不做部分解析。

## 完整性报告

新版头部必须具有 DCS 魔数；ECS 与未知魔数均拒绝。正文各边界、UTF-16、音节索引和控制字符均检查，异常词条不会输出成合法词典行。遇到损坏时返回已恢复条目并设置 `complete=false`；旧版仅缺元信息的提示不会设置该标记。

默认转换拒绝写出部分结果。显式 `--allow-partial` 导出后仍以退出码 3 和逐文件状态提醒检查。`complete=true` 只表示在支持的结构下未发现错误：当前没有验证头部摘要或与原软件比较总词数，恰好在完整词条边界截断的数据可能无法识别。
